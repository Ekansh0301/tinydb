# ADR-011: The design stage receives a trimmed architecture note, and tool reads are small

- **Date:** 2026-11-16
- **Status:** Accepted
- **Supersedes:** the Planner row of the hand-off table in ADR-003
- **Decision area:** D3 Hand-offs

## Context
ADR-003 said the planner receives the whole `ARCHITECTURE.md` and reads the repository through tools. The first run on GitHub (Actions run 43920591950, issue #7) stopped at stage 2 with "context cannot be made to fit the request limit". The note is about 10,400 characters (roughly 2,900 tokens), the spec about 600 words, and the model asked for 120- and 200-line ranges of `tinydb/table.py`. With the 7,000-token request limit measured in `experiment/model_probe.md`, there was no room left after two file reads. The agent then re-read the same ranges because earlier tool output had been dropped, and the stage ended. ADR-003 was wrong to assume the whole note and free-sized file reads would fit.

## Decision
- The design stage receives `ARCHITECTURE.md` reduced to its overview and component table, the **decision** line of each ADR, and the full constraints list (about 7,100 characters). The long context and consequences text of the ADRs is left out.
- `open_file` returns at most 80 lines per call (60 by default); tool output is capped at 2,600 characters; the design prompt tells the agent to read small ranges and not to repeat them.
- The rest of ADR-003 stands: the implementer sees the spec and the design, the tester sees the spec and the file list, and the reviewer sees the issue, the diff and the repository.

## Alternatives considered
- **Give the planner a model with a long context (NVIDIA).** Removes the limit, but those models are the reviewer tiers (ADR-006); using them as builders weakens the independence argument.
- **Summarise the architecture note with a model call.** Adds a step that can distort the document the assignment asks us to use. Rejected.
- **Raise the Groq prompt budget.** The limit is the provider's, not ours.

## Consequences
- The planner sees less of the A2 document than the study that produced it assumed. The omitted text is rationale, not rules; the rules (constraints) are kept in full.
- Smaller reads make exploring slower (more tool calls) but keep every request below the limit.
- Whether the trimmed note changes design quality is not tested here; it is listed as a limitation.
