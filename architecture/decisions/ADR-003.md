# ADR-003: Hand-offs are short written artifacts, not conversations

- **Date:** 2026-11-16
- **Status:** Superseded by ADR-011 (the planner hand-off row; see the run it names). The other rows still stand.
- **Decision area:** D3 Hand-offs

## Context
Each request must stay under about 7,000 tokens, and a model that reads another agent's reasoning tends to inherit its mistakes. What an agent does not see matters as much as what it sees.

## Decision
Each agent receives a fixed set of inputs, assembled by the orchestrator. Agents never see another agent's messages, only artifacts. Artifacts have a size cap (spec 1,200 tokens, design 1,200 tokens, test report 800 tokens); a stage whose artifact is over the cap fails its gate and is retried with a request to shorten it.

| Agent | Receives | Deliberately not given |
|---|---|---|
| Planner | sanitised issue text, `ARCHITECTURE.md`, read-only repo tools | any later stage output |
| Implementer | `spec.md`, `design.md`, repo tools | the raw issue text; the planner's conversation |
| Tester | `spec.md`, file list from `design.md`, repo at the implementer's commit | the implementer's conversation, the design rationale |
| Reviewer | issue text, `diff.patch`, repo at the PR head | `spec.md`, `design.md`, `test_report.md`, every conversation |

On a back-edge the next attempt additionally receives a short failure note written by code (failing test names and the first lines of the traceback, or the reviewer's findings), never the previous attempt's reasoning.

The repository is reached through tools (ADR-005, to be written) with truncated reads, so an agent reads what it needs instead of receiving whole files.

## Alternatives considered
- **Pass full transcripts.** Preserves detail, exceeds the token limit, and spreads errors. Rejected.
- **Pass summaries written by the previous agent.** Cheaper than transcripts, but still carries the previous agent's interpretation. Used only for artifacts that are the stage's required output.
- **Give every agent the raw issue.** Simple, but lets the implementer bypass the spec and reintroduces prompt-injection exposure at every stage (ADR-009).

## Consequences
- The implementer works from the spec rather than the issue, so an error in the spec is not corrected downstream; the spec gate (ADR-007) has to be strong.
- The reviewer cannot judge the implementation against the spec. It judges against the issue only, which is what a maintainer would do.
- Test: the hidden tests (written from the issue text) measure whether the lack of raw issue text harmed the implementer. If it did, this ADR is revisited.

## Note (2026-11-20)
The artifact size caps are enforced as word limits in the gates (specification 1,000 words, design 800 words), not as the token caps written above; `test_report.md` has no cap. The hand-off table for the reviewer, the implementer and the tester is as implemented (`workflow/autose/stages.py`); the planner row is superseded by ADR-011.
