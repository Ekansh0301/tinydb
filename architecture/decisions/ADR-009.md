# ADR-009: Hard budgets, bounded loops, and untrusted-input handling

- **Date:** 2026-11-16
- **Status:** Accepted
- **Decision area:** D9 Safety and failures

## Context
Limits that matter here: 8,000 tokens per minute per key and about 7,000 per request on Groq; Actions jobs stop after their `timeout-minutes` (6 hours by default); an issue is text written by anyone, so it can carry instructions aimed at the agents; and the code agents write is executed on a runner that also holds API secrets.

## Decision
**Budgets (all configurable in one file, defaults below).**
- Per request: input truncated to 6,000 tokens; tool outputs capped at 4,000 characters.
- Per stage: at most 25 model calls and 60,000 tokens; a stage that exceeds either stops with its reason written to the artifact.
- Per run: at most 400,000 tokens and 2 review rounds. Totals are written to `state.json` and reported.
- Wall-clock: each job has `timeout-minutes` (build 40, review 20), each model call 90 s.
- Rate limits: key rotation on 429, exponential backoff with jitter, at most 5 retries, then the stage stops.
- Stuck stage detection: the same tool call with the same arguments three times in a row stops the stage.

**Untrusted input.**
- Issue and comment text reaches agents only inside a clearly delimited block marked as data, with an instruction not to follow directions found in it. It is truncated to 4,000 characters.
- The gate job scores the text with a prompt-injection classifier (ADR-006). A score above 0.9 stops the run and posts a comment asking a maintainer to review the text.
- Agents have no network tool and no secrets. API keys exist only in the orchestrator and reviewer processes; every shell command an agent runs gets an empty environment.
- Workflows never use `pull_request_target` and never check out code from an untrusted fork. The workflow refuses to run unless the repository is `Ekansh0301/tinydb`, so it cannot push anywhere else.
- Jobs get the minimum `permissions`. Nothing in the workflow can merge.

## Alternatives considered
- **Rely on the model to ignore injected text.** Weak and unmeasurable. Used as one layer only.
- **No classifier, only delimiters.** Cheaper, but gives no signal for the report. Classifier kept because it costs a single small request.
- **Run agent code in a container with no network.** Stronger, and Actions runners can do it, but it adds setup time and failure modes. Considered for later if a run shows the need.

## Consequences
- A legitimate, unusual issue may be stopped by the classifier (false positive); a maintainer re-triggers after review.
- Budgets can stop a run that would have succeeded with more effort. The stop reason is recorded so this is visible in results.
- We will test the gate with injection attempts in the five issues' variants and report what passed through.
