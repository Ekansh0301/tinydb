# ADR-001: Split the work into three agents and one code step

- **Date:** 2026-11-16
- **Status:** Accepted, to be tested (decision experiment E1)
- **Decision area:** D1 Splitting the work

## Context
Six stages must run in order. Two properties of our setting shape the split. Every request to our free models must stay below about 7,000 tokens (8,000 tokens per minute per key on Groq, measured in `experiment/model_probe.md`), so no agent can carry the whole run in one conversation. And stages differ in what they must not know: a tester who has read the implementation will write tests that confirm it rather than tests that check the requirements.

## Decision
- **Planner** handles stages 1 and 2 (spec, then design). Both are read-only analysis of the issue and repository, and the design needs the spec in full.
- **Implementer** handles stage 3. It is the only agent that edits source files.
- **Tester** handles stage 4. It is given the spec and the list of files, not the implementer's conversation, so its tests come from the requirements.
- **Release** (stage 5) is code, not an agent. A pull request description can be built from the artifacts and the diff without a model, which removes one failure point.
- **Reviewer** handles stage 6 and is a fourth agent, described in ADR-008.

So there are four LLM roles in total (three build roles plus the reviewer), plus an orchestrator that is plain code (ADR-002).

## Alternatives considered
- **One agent for everything.** Simplest, but its context grows past our request limit, and the same agent would write the code and the tests that judge it. Rejected as the default, but kept as variant `single` in experiment E1 so the claim is measured and not assumed.
- **One agent per stage (six agents).** Maximum isolation, but spec and design are tightly coupled, and a separate design agent would only re-read the spec. It adds hand-offs without adding independence. Rejected.
- **Planner decides what to do next (dynamic planner).** More flexible, but harder to bound on a free-tier budget and harder to explain. Rejected in ADR-002.

## Consequences
- Each agent prompt stays small and specific.
- Implementer and tester are separate, which is what makes "new tests fail on the base commit" a meaningful check.
- More hand-offs mean more places where information can be lost; ADR-003 addresses this with compact artifacts.
- E1 compares `single` against this split on the same five issues, by stage pass rate and hidden-test result. If `single` does as well, this ADR is superseded.
