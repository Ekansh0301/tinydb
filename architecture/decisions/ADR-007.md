# ADR-007: Checks are code; one model call may only add objections

- **Date:** 2026-11-16
- **Status:** Accepted
- **Decision area:** D7 Checks

## Context
The assignment wants a check before each stage hands over. If an agent decides that its own work is good enough, the check is only an opinion. We want the final pass or fail decision to be reproducible.

## Decision
Each gate is a function in `workflow/autose/gates.py` that returns pass or fail plus a list of reasons. Agents never decide. The reasons are handed to the next attempt as plain facts.

| Stage | Check | Kind |
|---|---|---|
| 1 | Required sections present; every acceptance criterion in Given/When/Then form; no vague word in the outcome; every requirement has a criterion; at most 1,000 words. Then one short model call lists criteria that no automated test could decide; any it names fails the gate. | code, plus a model call that can only add objections |
| 2 | Every file named exists (or is marked NEW) and is not in a protected path; every function named exists in that file (or is NEW); every acceptance criterion appears in some row. | code |
| 3 | Diff not empty; only files named in the design (plus existing tests and the tester's file) changed; `compileall` and `import tinydb` succeed. | code |
| 4 | Every acceptance criterion has a test named `test_ac<N>_...`; at least one new test fails on the base commit (so the tests exercise the change); the whole suite passes on the new code. | code |
| 5 | The pull request is open (code); CI passes (the reusable workflow, evaluated by the `next` job). | code and Actions |
| 6 | The review is valid JSON, gives at least two checks with evidence, ran a command, and an approval has no medium or high findings; a rejection names an issue class and a finding. | code |

The testability call is the only place where a model takes part, and it can only fail a gate, never pass one.

## Alternatives considered
- **An LLM judge for every gate.** Cheap to write, but it varies between runs and tends to agree with the work in front of it. Rejected.
- **Only run the tests.** This misses a vacuous test suite and a spec that cannot be tested. The base-commit check and the criterion-to-test mapping address that.
- **A human check at each stage.** It defeats the purpose of the workflow; humans decide at the end.

## Consequences
- Gates can be wrong in the way code is wrong. Four early stops were bugs in the gates, not mistakes of the agents: a design table with a `|` inside a cell (a type hint) was parsed into the wrong columns, so a correct design was rejected (fixed, covered by `test_design_table_with_pipe_in_a_cell`); the planner wrote its criterion ids with a non-breaking hyphen (AC-1 spelled with U+2011), so the design gate reported every criterion as uncovered (Actions run 43923180454; the gates now normalise typographic hyphens, `test_typographic_hyphens_in_ids_are_accepted`); a criterion that covers two requirements was rejected; and a function name followed by a note was not found. Gate code needs its own tests, ideally written from recorded agent output.
- A strict gate stops runs that a human would have accepted. These stops are visible in `results.csv`.
- Because the tester sees only the spec, its tests inherit any mistake in the spec; the hidden tests, written from the issue text, are how this is measured.

## Amendment (2026-11-19, after Actions run 44391179801)
In the first recorded run of issue #5 the design gate crashed with `IsADirectoryError`: the planner named the directory `tests` as a file, the gate tried to read it, and the whole job ended with a traceback and no recorded reason. Two changes: a directory in the file column is now an ordinary gate failure ("name the file you will change"), and the orchestrator wraps every stage and gate so that an unexpected exception ends the run as a recorded stop with the reason `internal error in <stage>: <exception>`, never as a dead job. The fix is code version `autose-v1.1`; the runs on issues #7, #4 and #6 were made with `autose-v1`, which differs only by this change (`git diff autose-v1 autose-v1.1`).
